# Unity 智慧课程规划草案（总学时待教师确认）

版本日期：2026-10-26。用途：与任课教师确认课程目标、模块取舍与实验建设顺序；本文件不是已批准的教学大纲。

## 1. 课程定位与待确认事项

课程以 Unity 2021.3.45f2c1 为运行环境，在网页中嵌入简化的 Unity 实验编辑界面。学生创建允许的对象、选择预先编译的脚本行为、组合组件、设置开放参数并运行实验；脚本只读，不提供学生修改或编译源码的入口。

**总学时、教学周数、每周学时和理论/实训比例均待教师确认。** 当前只给出模块相对权重和先修关系，不锁定 48 或 64 学时。教师确认前，不应把下表的百分比直接当成学时或周次。

需要教师确认的最小信息：授课专业与年级、学生已有 C# 基础、总学时及每次连续课长度、是否要求独立编程考核、考核与补交规则、机房浏览器条件。教师确认后再形成逐次课表与正式教学大纲。

学生应达到的可观察目标：

1. 区分游戏对象、变换、组件与脚本行为，说明它们在实验中的作用。
2. 依据任务选择行为、布置对象，用运行证据检验预测，并能复现实验。
3. 阅读短 C# 片段，解释关键语句、输入条件和运行结果之间的联系。
4. 发现对象位置、组件选择、引用和运行状态方面的常见错误，并按步骤定位。
5. 说明编辑状态、运行快照与持久化存档的区别，准确描述保存边界。

本平台能够训练代码阅读、结果预测、组件组合和实验解释；**不能单凭这些实验认定学生已经具备独立编写、调试或重构 C# 脚本的能力**。若学校的课程目标包含独立编程，需要教师另设桌面 Unity/C# 编程作业并单独评价；这不改变本平台“学生不可编辑脚本”的边界。

## 2. 教材核验与使用方式

使用教材：马遥、沈琰编著《Unity 3D脚本编程与游戏开发》，人民邮电出版社，ISBN **9787115558756**。出版社微信认证微店列明第 1 版、2021 年 5 月；书名、作者和 ISBN 均可在该页直接核验。[出版社商品与目录页](https://detail.youzan.com/show/goods?alias=2fu23gugaokpd&from_source=gbox_seo)

该书共 13 章。下面按章节号码做课程主题映射，不转载全书目录。特别校正：第 2 章名称为“Unity基本概念与脚本编程”。书中覆盖基础脚本、物理与数学、界面、动画、特效与音频、资源与数据、AI、综合案例及进阶技术；得到电子书页面列出的目录与出版社页面一致，可交叉查验。[得到电子书目录（页面列出版方为人民邮电出版社）](https://www.dedao.cn/ebook/detail?id=z4R9BQ7pP4ZEaXYkx8KvRdljeyqo608g25w1m2bMAO9NnDL7gBGQr5VzJqrvmEVN)

**上述书目信息与章节主题是核验事实；以下模块、任务、权重和评价标准均为本课程的教学设计建议。** 第 12 章的原书综合案例只作为阅读与分析参考；课程拟用规模更小的练习关卡，不承诺复刻整章游戏。教材中的源码、素材和配套资源应依其授权使用，本规划不附全文、整套源码或视频资源。

## 4. 可重排模块结构

下表建议总教学量按 **100%** 分配：讲解、阅读与讨论占 **30%**，操作、观察与考核占 **70%**。这是分配建议，教师可调整。各行的讲解权重与实训权重均以全课为分母，行内相加等于模块权重。

| 模块 | 教材映射与学习重点 | 模块权重 | 讲解/实训权重 | 先修 | 对应任务及状态 |
|---|---|---:|---:|---|---|
| M01 对象与行为入门 | 第 1—2 章；对象、Transform、组件、脚本片段与运行状态 | 10% | 4% / 6% | 无；会使用浏览器 | 实验 01：场景搭建与小球运动，核心已验证 |
| M02 物理与空间推理 | 第 3—4 章；刚体、碰撞、方向与位置向量，单变量比较 | 15% | 4% / 11% | M01 | 实验 02：运动方向与目标区域，仅规划 |
| M03 事件与游戏界面 | 第 5 章；事件来源、显示状态、组件引用 | 10% | 4% / 6% | M01—M02 | 实验 03：触发计分与结果界面，仅规划 |
| M04 角色与动画状态 | 第 6 章；动画参数、状态、转换条件 | 10% | 3% / 7% | M01、M03 | 实验 04：角色待机与行走切换，仅规划 |
| M05 视听反馈 | 第 7—8 章；一次事件对应一次特效/音效，反馈与逻辑分工 | 10% | 3% / 7% | M03 | 实验 05：目标命中的视听反馈，仅规划 |
| M06 资源与依赖 | 第 9 章；模板、资源引用、加载状态、依赖关系 | 10% | 3% / 7% | M01、M05 | 实验 06：主题资源包切换，仅规划 |
| M07 数据与复现 | 第 10 章；序列化、保存字段、加载验证 | 10% | 3% / 7% | M01；结合 M06 更佳 | 实验 07：关卡配置保存与恢复，仅规划；实验 01 仅作现有保存示例 |
| M08 简单游戏 AI | 第 11 章；巡逻、发现与追踪的有限状态 | 10% | 3% / 7% | M02、M04 | 实验 08：巡逻与追踪，仅规划 |
| M09 综合任务与改进 | 第 12—13 章；组合前述模块，分析复用与对象池概念 | 15% | 3% / 12% | M03—M08；依选定关卡裁剪 | 实验 09：微型收集/潜行关卡，仅规划 |
| **合计** | | **100%** | **30% / 70%** | | |

推荐顺序为 M01 → M02 → M03，随后 M04 与 M05；M06 与 M07 可相邻安排，M08 在角色与空间基础完成后进行，M09 最后。若压缩课时，应先缩小每个实验的对象数和扩展项，再决定 M04—M08 哪些仅保留教师演示与读码；不能在缺少行为库时把规划实验直接发给学生。

确定总学时 H 后，先按权重估算各模块学时，再按学校的课次粒度取整；把取整差额统一回填到 M09 的复习/展示，不得使总数偏离 H。先分配模块总学时，再分配其讲解与实训，最后按先修关系排课。正式版需再次核对“每模块学时之和 = 每次课学时之和 = H”。当前不列未经确认的周次和小时数。

## 5. 各模块实训内容与验收建议

以下行为名称除实验 01 的 `none/drop/launch` 外均为**拟建的行为库标识**，不是当前可选脚本。所有新增行为均应由开发方预编译，学生只能选择、组合和修改允许的参数。

| 实验 | 最小对象集合与学生任务 | 行为库/资源依赖 | 提交证据 | 建议客观通过条件 |
|---|---|---|---|---|
| 01 场景搭建与小球运动 | 地面 1、小球 1；拖动布置场景，在同一位置比较三种行为，停止恢复并保存重开 | 已有 `none`、`drop`、`launch`；地面/球体模板；直接平移与XYZ轴柄已验收 | 初始/运行/恢复截图、平移坐标对照、短读码答案 | 下落触地约 Y=0.5；水平抛出 X 增大且 Y 下降；停止/刷新恢复目标编辑设置。详见任务单 |
| 02 运动方向与目标区域 | 地面、球体、目标区各 1；预测运动方向，调整起点使球进入固定目标区 | 拟建 `FixedVelocity`（教师审核的速度档位）、`TargetTrigger`、轨迹/事件记录；继承真实物理 | 两次不同起点的对照、命中日志、向量方向说明 | 同一行为下仅改起点；一次命中一次未命中；日志与观察一致；解释位移与初速度区别 |
| 03 触发计分与结果界面 | 球体、两个触发目标、计分文本、结果面板；绑定触发与显示引用 | 拟建 `CollectOnce`、`ScoreCounter`、`WinPanel`；UI模板和引用选择器 | 引用配置图、运行前后计分图、事件顺序表 | 每目标只计一次；两次收集后结果显示一次；停止恢复零分；无目标引用有明确提示 |
| 04 角色待机与行走切换 | 角色 1、路径点 2；选择移动行为和动画参数映射 | 拟建 `WaypointMover`、`AnimatorDriver`；已授权角色模型、固定动画控制器 | 状态转换截图、参数/状态对照表 | 停止移动时待机、移动时行走；转换条件与只读逻辑相符；停止后恢复起点与初态 |
| 05 目标命中的视听反馈 | 球体、目标、粒子、音源；把一次命中绑定到视听反馈 | 拟建 `HitFeedback`、粒子/音频白名单；复用事件记录；浏览器音频启用提示 | 命中前后图、反馈事件记录、听辨确认表 | 一次命中记录一次播放请求；特效出现后结束；未命中不播放；重启无重复订阅。听到声音与收到播放请求分别记录 |
| 06 主题资源包切换 | 展示底座、展示物、两组固定素材；选择资源包并观察引用 | 拟建 `ApprovedAssetSelector`、加载状态/依赖面板；资源清单和授权信息 | 两主题截图、引用关系图、加载结果 | 切换后对象绑定目标资源；所需依赖齐全；缺失时保留旧场景并显示错误；本任务不要求网络热更新 |
| 07 关卡配置保存与恢复 | 至少 3 个允许对象；保存布局和允许参数，修改后恢复 | 拟建多实验独立存档、显式加载和格式版本验证；读取配置面板 | 保存前/修改后/恢复后对照、字段核对表 | 加载后对象数、位置、行为和参数一致；非法版本不覆盖场景；与运行快照区分；不得假定当前实验 01 已有导出/导入按钮 |
| 08 巡逻与追踪 | 敌人、玩家目标、两巡逻点、障碍；布置发现/失去目标场景 | 拟建 `PatrolChaseFSM`、可视状态日志、教师预烘焙导航区域；固定阈值档位 | 三种状态证据、转换条件表、一例无法到达说明 | 无目标时巡逻；进入可见范围时追踪；失去目标后按约定恢复；状态日志与场景一致；无路径有可解释反馈 |
| 09 微型综合关卡 | 玩家、有限目标、出口、一个守卫及结果UI；复用已放行组件形成小关卡 | 拟建 `LevelRules` 及前序白名单；可选 `PooledSpawner` 为进阶演示，不能成为未建设的硬依赖 | 可复现操作说明、初始布局、成功/失败证据、组件依赖图、改进记录 | 存档重开仍可复现；成功和失败条件各触发一次；没有悬空引用；逐条说明组件职责；评价设计取舍而非对象数量 |

实验 09 的最小可交付版本应限制在单场景、有限目标、固定行为组合；不要求制作完整商业游戏。第 13 章可采用“看日志比较创建/复用次数、解释对象池”的扩展阅读。协程与事件机制以现有预设脚本的执行顺序解释为主，不把“学生写出对象池或事件系统”列为平台内达成目标。

## 6. 每个实验发布前的内容合同

为防止“课程目录已有但实验不能做”，每个实验必须具备下列内容才可标为可开课：

| 项目 | 必需内容 |
|---|---|
| 身份与映射 | 稳定 `lab_id`、标题、版本、适配引擎、教材章节/节号、先修实验 |
| 学习目标 | 2—4 条能用行为或证据判断的目标，并注明是否包含代码阅读 |
| 对象与能力 | 可创建对象清单、数量上限、变换权限、脚本白名单、可配置参数与范围、资源授权 |
| 读码材料 | 与预编译版本一致的短片段；解释关注点；不显示可编辑入口 |
| 操作任务 | 从进入实验到提交的逐步动作；初始状态；运行/停止/重置和保存语义 |
| 观察与验证 | 预期现象、日志字段、数值容差、允许的物理波动、失败案例和恢复方法 |
| 状态与存档 | 编辑/运行权限；快照恢复；持久化范围、存档版本、异常加载处理 |
| 评价证据 | 交什么、如何命名、评分点、通过条件；没有实现自动评分时采用教师核验 |
| 视频关联 | 外部系统资源 ID 与关联知识点；视频缺失时仍有足以完成任务的文字说明 |
| 放行记录 | 构建版本、操作验收记录、截图/日志位置、验收者与日期；尚未验收的功能不进入必做项 |

视频字段仅作课程内容登记：`video_system_resource_ids`（外部系统真实资源 ID 列表）、`video_topic`、`related_step_ids`。当前资源 ID 保持空列表表示尚未由用户登记；不杜撰已存在的视频，不建立播放器或接口，也不把观看进度当成本实验运行证据。

## 7. 教学与评价建议

每次实验建议采用“先预测 → 独立操作 → 保留观察 → 对照解释 → 停止恢复 → 保存复现”。教师先用一个最小例子说明对象和脚本职责，再让学生独立完成一个改变条件的对照，最后解释一处读码问题。

全课成绩建议为：平时实训及证据 45%、代码阅读与解释 20%、综合任务 25%、过程参与与复现实验 10%，合计 100%。这只是提案，需遵守学校考核制度。若 M09 不开设，应在正式课表中重新分配其成绩比例，不能沿用缺失项目的分母。

实训评分应依据对象配置、可复现现象、解释与排错过程，不以“点过运行”或“界面步骤全部打勾”直接判满分。不要求学生证明平台未提供的功能。相同场景截图不能单独证明学生理解脚本，可用简短口头抽问或个性化初始坐标复核。

## 8. 建设与开课顺序

1. 完成实验 01 的核心与平移能力放行，教师试做任务单，确认术语和证据要求。
2. 教师确认总学时、学生基础及独立编程目标，再把百分比转换为课表。
3. 按选定课表逐实验建立内容合同与预编译行为库。优先完成 M02—M03，再扩展视听、资源、AI。
4. 对每个新实验分别验证正常操作、错误操作、运行停止、存档恢复；通过后再从“规划”改为“可开课”。
5. 用户在自有视频系统完成视频管理后，提供资源 ID，由课程内容登记关联；不扩展到视频系统开发。
