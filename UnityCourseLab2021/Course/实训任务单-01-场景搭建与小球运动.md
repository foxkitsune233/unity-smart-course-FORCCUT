# 实训任务单 01：场景搭建与小球运动

任务 ID：LAB-01。版本日期：2026-10-26。运行环境：Unity 2021.3.45f2c1 网页实验。课程总学时与本实验课时由教师确定，本单不预设课时。

教材关联：第 1 章的运动入门、第 2 章的对象/组件/变换、第 3 章的刚体与碰撞、第 4 章的位置与向量；保存环节可引入第 10 章的持久化概念。书目信息见[出版社页面](https://detail.youzan.com/show/goods?alias=2fu23gugaokpd&from_source=gbox_seo)。这些是知识点关联；本任务是课程自拟练习。

## 一、完成后你应能做到

1. 创建地面和小球，区分“选择对象”“改变位置”“选择行为”三个动作。
2. 比较静止、重力下落和水平抛出的结果，用坐标和接触记录支持判断。
3. 说明刚体、重力开关和初始速度在只读脚本中的作用。
4. 停止运行恢复起点，保存后刷新，在相同浏览器和站点恢复实验配置。

脚本由平台预先编译。你可以阅读关键代码、选择行为，不能修改或编译代码。此任务不要求编写 C# 程序。

## 二、开始前检查

由教师提供实验网址。开发验证地址为 `http://127.0.0.1:8088/`，只适用于正在本机运行实验服务的电脑；学生统一访问地址由教师另行提供。等待 Unity 加载完成，看到“编辑场景”后开始。

本任务只需要 1 个地面和 1 个小球。若打开时已有上次存档，先核对对象列表；已有这两个对象时直接复用，不要重复点击添加。若有多余对象而当前版本没有删除功能，请教师提供干净环境或确认可以复用的对象，不要自行清除浏览器全部数据。

核心步骤 A—G 与步骤 H 的直接拖拽、三轴移动均已通过原型浏览器验收，证据见 `Evidence/browser-tests.json` 和 `Evidence/browser-movement-tests.json`。教师课前应在学生实际浏览器复核；若个别设备不满足条件，可安排数字输入作为操作替代并记录原因。

## 三、操作与观察

### A. 建立一个可比较的初始场景

1. 在编辑状态，从“项目资源 / Project”中把“地板”和“小球”拖到场景。拖入位置决定X/Z，默认地板Y=-0.1、小球Y=3。也可使用原有“＋”快捷按钮；若对象已存在则复用。
2. 在左侧选择地面，确认位置为 `X=0，Y=-0.1，Z=0`；输入后按 Tab 或点另一输入框提交。地面保持“静止”。
3. 选择小球，设置 `X=0，Y=3，Z=0`。点击一个空白面板区域结束输入，核对右侧数值。
4. 右键拖动场景以旋转观察视角，滚轮缩放；看不清时点“恢复视角”。视角变化不等于对象位置变化。
5. 记录小球起点和地面位置，截取“初始配置图”，必须能看到对象列表、球的位置和行为。

默认地面尺寸为 10×0.2×10，中心 Y=-0.1，因此上表面在 Y=0。默认球直径为 1，位置表示球心；不要把球心高度当成球底高度。本任务不要求修改朝向和尺寸，也不假设界面提供这些编辑功能。

### B. 对照 1：静止

1. 选择小球，把“预设行为”设为“静止 · 不添加运动行为”。
2. 先写预测：运行后小球会不会下落？理由是什么？
3. 点“运行”，观察约 2 秒，记录选中球的高度和接触事件。
4. 点“停止”。确认回到编辑状态，位置仍为 `(0,3,0)`。

预期：本预设不添加 Rigidbody 运动组件，小球保持起点。不能把这一结果解释成“Unity 没有重力”；这里是小球没有启用对应运动行为。

### C. 对照 2：重力下落

1. 确认小球仍在 `(0,3,0)`，选择“重力下落 · DropBehavior”。
2. 阅读右侧片段，找到添加 `Rigidbody` 和 `useGravity = true` 的语句。
3. 先预测高度如何变化，再点“运行”。保持小球被选中，观察高度下降和接触事件出现。
4. 待球触地并稳定后截图，记录稳定高度及是否有接触事件；随后点“停止”。
5. 检查小球回到 Y=3，行为仍为重力下落。

预期：球心最后约为 Y=0.5，常规验收可采用 `0.45≤Y≤0.55`，并且至少发生一次接触。该范围只用于默认球和地面配置。接触事件表示发生接触的记录，不能直接当作当前有几个对象或持续接触多少秒；不要求每次试验恰好记录一次。

### D. 对照 3：水平抛出

1. 停止后确认起点仍为 `(0,3,0)`，选择“水平抛出 · LaunchBehavior”。
2. 在只读片段中找到 `new Vector3(2, 0, 0)`：它表示固定初始速度为正 X 方向每秒 2 个场景单位，初始 Y、Z 速度为 0。本版本没有修改速度的入口。
3. 预测 X、Y、Z 分别如何变化，再点“运行”。在球触地前观察；停止前可从右侧坐标读取当时值。
4. 截图或记录：X 比起点增大，Y 低于起点，Z 大致不变。点“停止”，检查起点和行为恢复。

预期：初始竖直速度为 0 仍会受重力向下运动；“水平抛出”不意味着始终沿水平直线飞行。运行帧率和手动截图时刻会不同，本任务不要求同学在完全相同的一帧获得相同坐标。不要用触地后滑动距离代替飞行阶段的比较。

### E. 改变起点，做一次单变量比较

1. 保持同一地面、同一小球与“重力下落”，将球的位置设为 `(0,4,0)`。
2. 比较从 Y=3 与 Y=4 下落：先预测哪一次更晚触地，再运行观察。可以记录大致触地时刻，但手动读时只作定性支持，不作精确自由落体测量。
3. 每次运行前写下起点，每次运行后停止恢复。说明你改变了哪个条件，保持了哪些条件。

预期：较高的起点通常需要更长时间触地，最终球心仍约为 Y=0.5。当前行为不开放质量、重力大小、弹性或阻力调节，不要声称本实验完成了这些参数的对比。

### F. 验证“停止恢复”和“保存”不是同一件事

1. 编辑状态设置球为 `(0,4,0)`、行为为“重力下落”，记为目标编辑配置。
2. 点“运行”，等球落地后点击“保存实验”或按 Ctrl+S。
3. 点“停止”。球应回到 `(0,4,0)`，不是留在落地位置。运行中保存的是本次运行前的编辑配置。
4. 核对行为和位置后，再在编辑状态点一次“保存实验”。观察实验记录中的保存提示。

“停止”恢复本次运行前的内存快照；“保存实验”把编辑配置写到浏览器存档。停止不会自动等同于永久保存。运行过程中创建对象、改坐标、拖拽和改行为应被禁止；需要修改时先停止。

### G. 刷新恢复

1. 仍使用同一电脑、同一浏览器、同一实验地址，刷新页面，等待重新加载完成。
2. 核对对象列表中仍有地面和小球，小球位置为 `(0,4,0)`，行为为重力下落，当前处于编辑状态。
3. 截取“刷新恢复图”，然后再运行一次，确认恢复的是可以继续实验的配置。

存档只属于当前浏览器和站点的 localStorage；换浏览器、换域名/端口、换电脑、使用会话结束后清理数据的模式或清除站点数据，都可能无法看到原存档。当前没有账户、云端同步、可交给教师的存档文件下载，也不是桌面 Unity 的 `.unity` 工程。截图和报告按教师指定方式提交，不能把“点了保存”当成“老师已收到作业”。

### H. 场景直接平移练习

1. 停止运行并选择小球，先把起点设为 `(0,3,0)`。
2. 左键按住球体本身拖动后松开。观察 X/Z 改变、Y 保持 3；这是水平 XZ 平面平移，不是沿屏幕上下方向改变高度。
3. 拖动 X 轴柄，核对只有 X 改变；拖动 Y 轴柄，核对只有 Y 改变；拖动 Z 轴柄，核对只有 Z 改变。右侧位置数值应同步更新。
4. 用数字输入恢复 `(0,3,0)`，验证精确输入与场景平移控制的是同一个对象。再拖动并保持左键按住，按 Esc 取消本次移动，确认回到拖动开始时的位置；松开鼠标。没有通用撤销按钮。
5. 拖动得到一个仍位于地面范围内、且球高于地面的新起点，记录坐标。运行、停止，核对回到这个新起点；保存、刷新后核对相同坐标。面板显示两位小数，存档保留底层更精确的位置，不要求手抄数值超出显示精度。
6. 运行时尝试拖动对象，观察编辑被禁用且轴柄隐藏；停止后应恢复可编辑状态。不要把物理运动误认为拖拽编辑成功。

截图不要求轴柄或对象恰好落在指定像素位置。选择、右键视角操作和左键平移的用途不同；拖拽不容易定位时先点“恢复视角”，再从列表选球。始终可用数字输入完成精确定位。

### I. 像Unity一样挂载脚本组件

本部分放在A—H的默认静止地面比较之后，避免把“移动地板”混入基础下落数据。

1. 停止运行。从项目资源把“平台往复移动”拖到左侧地面层级条目，确认右侧出现 `PlatformMoveBehavior (Script)` 组件卡片。也可以把脚本直接拖到场景中的地板表面。
2. 选中地面，把“自转”拖入右侧虚线“脚本组件”区域。确认同时出现平台移动和 `SpinBehavior (Script)`。
3. 选中小球，把已有运动组件用右侧“×”移除，再从资源面板把“重力下落”拖到场景小球上。随后可拖入“自转”进行组合。
4. 再试把“水平抛出”拖到已有重力下落的小球上，观察冲突提示；原有组件不应被覆盖。尝试把下落脚本拖到地板上，应收到不适用提示。
5. 把地板与小球恢复到 `(0,-0.1,0)` 和 `(0,3,0)`，运行观察：地板沿X往复移动并绕Y自转，小球下落并与地板接触。地板每侧位移约1.5单位，自转约每秒45度；这些参数固定，本任务不要求修改。
6. 停止，确认地板位置、朝向和组件恢复运行前配置。保存后刷新，核对两个对象的组件组合仍在。
7. 复做A—G时，先停止并移除地板上的平台移动和自转，也移除小球上的自转，恢复静止地面和单一运动脚本。

同一个运动脚本不能重复挂载，一个物体不能同时使用两个运动脚本；自转作为独立组件可以组合。脚本挂载只改变编辑配置，点“运行”后才执行。这里拖入的是平台内置预编译脚本，不是从电脑上传C#文件。

## 六、常见误解与排查

| 现象或说法 | 先检查与正确解释 |
|---|---|
| “我改了位置但小球没变” | 是否选中地面而非小球？是否仍在运行？输入是否有效并已提交？列表名称与属性面板要一致 |
| “球不下落说明物理坏了” | 小球是否选了静止？重力行为是否已选中？是否点了运行？静止预设的悬空是预期结果 |
| 球一直下落或落到地面之外 | 先停止，恢复地面中心与球起点；确认地面存在，球在地面边界内；不要通过不断新增对象尝试修复 |
| “触地 Y 必须为 0” | 位置是球心；默认半径0.5，地面上表面Y=0，所以球心约0.5 |
| “抛出就是不受重力” | launch同样开启重力；固定速度是运行开始时赋予，不会抵消后续重力 |
| “停止后丢失了运行成果” | 本实验刻意恢复运行前编辑快照，便于重复比较；运行轨迹不作为编辑布局永久保存 |
| 刷新后看不到存档 | 地址含协议/域名/端口是否一致？是否同一浏览器配置？是否真的出现保存提示？站点数据是否被清理？ |
| 运行期间输入框或拖拽无效 | 这是状态限制；先停止再编辑，不绕过限制 |
| “我已经完成C#编程” | 本任务证明行为选择、代码阅读与解释；没有学生源码编辑，不能据此认定独立编程能力 |
